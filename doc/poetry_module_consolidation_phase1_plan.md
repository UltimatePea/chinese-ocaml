## Phase 1 目标：数据加载器统一化

### 当前问题分析

在 `src/poetry/data/` 目录下发现多个功能重复的数据加载器：

1. **expanded_data_loader.ml** - 扩展诗词数据加载器
2. **externalized_data_loader.ml** - 外化数据加载器  
3. **poetry_data_loader.ml** - 统一诗词数据加载器
4. **rhyme_data_loader.ml** - 韵律数据加载器
5. **tone_data_loader.ml** - 声调数据加载器

### 重复代码分析

每个加载器都包含：
- 相似的错误处理类型和函数
- 重复的文件读取逻辑
- 基本相同的JSON解析功能
- 类似的数据验证机制

### 统一策略

#### 1. 创建统一数据加载器核心
创建 `unified_data_loader.ml` 作为所有数据加载的核心：
- 统一错误处理类型
- 通用文件读取接口
- 标准化的JSON解析
- 可扩展的数据验证框架

#### 2. 兼容性保证
保持现有模块作为兼容层：
- 现有模块重新导出统一加载器的功能
- 保持100%的API兼容性
- 不破坏现有的依赖关系

#### 3. 渐进式迁移
- Phase 1a: 创建统一核心
- Phase 1b: 迁移第一个模块（expanded_data_loader）
- Phase 1c: 逐步迁移其他模块
- Phase 1d: 清理和优化
