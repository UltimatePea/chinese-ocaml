## 概述

骆言文件系统模块（文件系统.ly）为骆言编程语言提供了全面的文件系统操作功能。该模块支持跨平台文件操作，包括文件读写、目录管理、路径处理、权限控制等核心功能，同时完全支持中文文件名和路径。

## 模块设计理念

### 诗意编程风格
文件系统模块遵循骆言的诗意编程传统，所有函数名都使用优雅的中文命名：
- `读取文件` 而非 `read_file`
- `创建目录` 而非 `mkdir`
- `拼接路径` 而非 `join_path`

### 函数式编程范式
采用函数式编程设计，支持：
- 柯里化函数（如 `写入文件` 返回接受内容的函数）
- 不可变数据结构
- 纯函数式路径处理

### 跨平台兼容性
底层使用OCaml的Unix模块，确保在Linux、Windows和macOS上的一致行为。

## 错误处理

### 异常类型
文件系统操作可能抛出以下异常：
- `文件不存在` - 尝试访问不存在的文件
- `权限不足` - 没有足够权限执行操作
- `磁盘空间不足` - 写入操作时磁盘空间不够
- `路径无效` - 提供了无效的路径
- `系统错误` - 底层系统调用失败

### 错误处理模式
```ly
「:安全的文件操作:」
尝试 「
  设「内容」为读取文件 『可能不存在的文件.txt』 在
  打印 内容
」 捕获 异常 -> 「
  打印 『文件读取失败: 』 + 异常消息 异常
」

「:检查文件存在性后操作:」
若 文件存在 『config.txt』 则
  设「配置」为读取文件 『config.txt』 在
  「:处理配置内容:」
余者
  打印 『配置文件不存在，使用默认配置』
```

## 跨平台兼容性

### 路径分隔符
模块自动处理不同操作系统的路径分隔符：
- Unix/Linux/macOS: `/`
- Windows: `\`

```ly
「:获取系统路径分隔符:」
设「分隔符」为路径分隔符 在  「:Windows上为\，Unix上为/:」
```

### 文件名限制
注意不同操作系统的文件名限制：
- Windows: 不支持 `< > : " | ? * \` 等字符
- Unix: 支持除 `/` 和空字符外的所有字符
- 长度限制: 大多数系统支持255字节的文件名

## 最佳实践

### 1. 错误处理
- 总是检查文件存在性再进行操作
- 使用 `尝试...捕获` 处理可能的异常
- 提供有意义的错误消息

### 2. 资源管理
- 及时清理临时文件
- 大文件操作后检查磁盘空间
- 避免在循环中重复打开同一文件

### 3. 路径处理
- 使用 `拼接路径` 而非字符串拼接
- 规范化路径以避免 `..` 和 `.` 问题
- 检查路径有效性

### 4. 权限安全
- 创建文件前检查目录写权限
- 设置合适的文件权限
- 避免创建全局可写文件
