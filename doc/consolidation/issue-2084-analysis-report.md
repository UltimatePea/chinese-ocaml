## 🏗️ 整合策略

### Phase 1: 韵律系统整合 (优先级：最高)
**目标**: 131个韵律文件 → 25个核心模块

**现有韵律目录结构**:
```
src/poetry/rhyme/          # 主韵律目录
src/poetry/rhyme_data/     # 韵律数据
src/poetry/rhyme_groups/   # 韵律分组
src/poetry/data/rhyme_groups/  # 数据层韵律分组
```

**整合计划**:
1. **统一韵律核心** (`src/poetry/rhyme/core/`)
   - 合并 `rhyme_engine.ml`, `rhyme_validator.ml`
   - 整合所有韵律相关核心逻辑

2. **韵律数据整合** (`src/poetry/rhyme/data/`)
   - 合并 `rhyme_data/` 和 `data/rhyme_groups/` 的重复内容
   - 统一韵律数据加载和管理

3. **韵律查询系统** (`src/poetry/rhyme/query/`)
   - 整合查询引擎和匹配逻辑
   - 统一韵律检索接口

### Phase 2: 数据管理系统整合
**目标**: 129个数据文件 → 15个核心模块

**现有数据目录结构**:
```
src/poetry/data/           # 主数据目录
src/poetry/data/core/      # 核心数据类型
src/poetry/data/loaders/   # 数据加载器
src/poetry/data/managers/  # 数据管理器
```

**整合计划**:
1. **数据加载器统一**
   - 合并所有 `*_loader.ml` 文件
   - 创建统一数据加载接口

2. **数据管理器整合**
   - 整合 `data_manager*.ml` 系列文件
   - 统一数据存储和检索逻辑

### Phase 3: 缓存系统优化
**目标**: 28个缓存文件 → 8个核心模块

**现有缓存结构**:
```

```

**整合计划**:
1. **缓存核心合并**
   - 整合缓存操作逻辑
