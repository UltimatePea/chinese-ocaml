## 🛠️ 测试工具和脚本

### 标准测试运行器
```bash
# 基础测试运行
./test/run_tests.sh

# 增强测试运行器 (支持并行和详细报告)
./test/enhanced_test_runner.sh [选项] [模式]

# 选项:
#   -p, --parallel JOBS     并行作业数
#   -v, --verbose          详细输出
#   -c, --coverage         生成覆盖率报告
#   -t, --timeout SEC      测试超时时间

# 模式:
#   unit                   只运行单元测试
#   integration           只运行集成测试
#   performance           只运行性能测试
#   all                   运行所有测试
#   quick                 快速测试 (跳过性能测试)
```

### 覆盖率分析
```bash
# 生成覆盖率报告
dune runtest --instrument-with bisect_ppx
bisect-ppx-report html --source-path . --coverage-path _build/

# 查看覆盖率摘要
bisect-ppx-report summary --coverage-path _build/
```

### 测试调试
```bash
# 运行单个测试
dune exec test/unit/test_lexer.exe

# 详细调试模式
VERBOSE=true ./test/enhanced_test_runner.sh unit

# 查看测试日志
cat _build/default/test/unit/test_lexer.exe.log
```

## 📋 常见问题和解决方案

### 测试失败处理
1. **编译错误**
   - 检查依赖模块是否正确导入
   - 验证API调用是否与最新版本匹配
   - 查看dune配置是否正确

2. **断言失败**
   - 检查预期值是否仍然正确
   - 验证测试数据是否需要更新
   - 确认功能逻辑是否已变更

3. **超时问题**
   - 检查是否存在死循环
   - 优化测试数据大小
   - 考虑增加超时时间或拆分测试

### 覆盖率问题
1. **覆盖率下降**
   - 识别未覆盖的新代码
   - 添加针对性测试用例
   - 检查是否有废弃代码需要清理

2. **覆盖率报告异常**
   - 验证bisect_ppx配置正确
   - 检查dune文件中的preprocess配置
   - 清理旧的覆盖率数据文件

### 性能问题
1. **测试运行缓慢**
   - 启用并行测试执行
   - 优化测试数据和算法
   - 考虑拆分大型测试

2. **资源消耗过高**
   - 检查内存泄漏
   - 优化测试数据结构
   - 限制并发测试数量

## 🚀 最佳实践建议

### 测试编写
1. **遵循AAA模式**: Arrange (准备) - Act (执行) - Assert (断言)
2. **一个测试一个断言**: 每个测试函数专注于验证一个特定行为
3. **清晰的测试名称**: 测试名称应能清楚说明测试的内容和预期
4. **独立的测试**: 测试之间不应有依赖关系

### 测试数据管理
1. **数据驱动测试**: 使用参数化测试处理多种输入情况
2. **测试数据分离**: 将测试数据放在专门的文件或模块中
3. **最小化数据**: 使用最小必要的测试数据来验证功能

### 持续改进
1. **定期重构**: 定期清理和重构测试代码
2. **覆盖率监控**: 建立覆盖率趋势监控
3. **性能基准**: 建立测试性能基准线并定期检查
