## 问题概述

经过全面分析，项目的测试基础设施存在严重的系统性问题：

### 1. 测试覆盖率危机
- **当前覆盖率：0.00%** - 这表明测试配置存在根本问题
- 大量测试文件存在但未能正确运行或计算覆盖率
- bisect_ppx配置可能存在问题

### 2. 测试文件组织混乱
- 测试目录包含**200+测试文件**，但缺乏统一组织
- 存在大量重复和冗余测试（如多个`comprehensive`、`enhanced`版本）
- 多个代理创建了功能重叠的测试文件

### 3. 测试配置不一致
- dune配置中测试定义不统一
- 部分测试缺少必要的库依赖
- bisect_ppx预处理器配置不一致

### 4. 测试分类模糊
- unit、integration、performance测试边界不清
- 缺乏明确的测试优先级和分组
- 测试命名约定不统一

## 技术实施细节

### 覆盖率修复策略
```bash
# 清理旧覆盖率数据
find . -name "*.coverage" -delete

# 重新配置bisect_ppx
dune clean
dune build --instrument-with bisect_ppx

# 运行测试并生成覆盖率
dune runtest --instrument-with bisect_ppx
bisect-ppx-report html
```

### 测试清理原则
1. **保留原则**：保留功能完整、维护良好的测试
2. **合并原则**：合并功能重复但各有特色的测试
3. **删除原则**：删除过时、无效或严重重复的测试

### 测试分层策略
```
test/
├── unit/           # 单元测试 - 测试单个模块/函数
├── integration/    # 集成测试 - 测试模块间交互
├── e2e/           # 端到端测试 - 完整编译流程
├── performance/   # 性能测试 - 基准测试和性能回归
├── fixtures/      # 测试数据和辅助文件
└── utils/         # 测试工具和辅助函数
```
