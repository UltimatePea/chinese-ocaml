## 执行摘要

本文档提供代理日常工作中的**实用**质量控制检查清单。基于Delta代理的反馈，大幅简化原有流程，专注于核心质量要点，避免过度流程化。

**核心原则**: 
- 维护者@UltimatePea拥有最终决策权
- 代理仅提供技术建议
- 保持流程简洁实用
- 紧急情况优先处理

## 📋 代理启动基础检查 (5分钟)

### 快速环境确认
```bash
# 必做检查 (2分钟)
- [ ] git status && git log --oneline -3
- [ ] python scripts/github/github_auth.py --test-auth  
- [ ] dune build (确认项目可构建)

# GitHub状态 (3分钟)
- [ ] gh issue list --state open | head -5
- [ ] gh pr list --state open
- [ ] 识别维护者@UltimatePea的评论或要求
```

## 🎯 任务优先级 (简化版)

### 优先级定义
```yaml
🚨 立即处理:
  - 维护者明确要求的任务
  - 生产环境Bug
  - CI构建失败

🔥 今日处理:  
  - 维护者评论的PR/Issue
  - 阻塞他人的问题

📋 常规处理:
  - 其他技术任务
  - 代码改进
```

## 🔧 PR质量基础要求

### PR提交前 (3分钟检查)
```bash
- [ ] dune build (构建成功)
- [ ] git diff --stat (确认变更合理)
- [ ] 写清楚"Fix #issue-number"
- [ ] 一句话描述解决了什么问题
```

### PR内容要求
- **必须**: Fix引用、问题描述、技术方案
- **可选**: 代理技术建议
- **记住**: 维护者可以忽略所有代理建议

## 👥 代理协作基础规则

### 避免冲突
- 开始前检查是否有其他代理在处理相同问题
- 大的变更在Issue中声明计划
- 不确定时询问维护者

### 代理建议格式
```markdown
**[代理名]**: ✅建议通过 / ⚠️建议修正 / 🚫建议暂停
理由: [一句话技术理由]
```

## ⚡ 紧急情况处理

### 紧急修复
- 跳过所有代理审查流程
- 直接请求维护者@UltimatePea批准
- 事后补充文档和测试

### 当流程阻塞时
- 维护者权威高于所有流程
- 可直接请求维护者裁决
- 记录决策原因供后续参考

## 💡 质量改进建议

### 技术债务
- 发现明显问题时创建Issue
- 小问题随手修复
- 大问题制定计划

### 持续改进
- 基于实际使用效果调整流程
- 简化不实用的检查项
- 保持文档更新

## ⚠️ 重要提醒

1. **维护者至上**: @UltimatePea的决定最终且绝对
2. **代理协助**: 我们是技术助手，不是决策者
3. **实用主义**: 流程服务于质量，不是反之
4. **灵活应变**: 特殊情况特殊处理
