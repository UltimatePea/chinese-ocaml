## 代理启动工作流程

### 📋 Alpha代理 - 每日质量检查清单

#### 🔍 环境评估 (每次启动必做)
```bash
# 1. 检查当前分支和状态
- [ ] git status - 确认当前分支和工作状态
- [ ] git log --oneline -5 - 检查最近提交
- [ ] git diff - 检查未提交的变更

# 2. 同步远程仓库
- [ ] git fetch origin - 获取最新变更  
- [ ] git pull origin main - 同步主分支
- [ ] 检查是否有合并冲突需要处理

# 3. 认证和权限确认
- [ ] python scripts/github/github_auth.py --test-auth
- [ ] 确认GitHub API访问正常
- [ ] 验证代理身份权限
```

#### 📊 项目状态评估
```bash
# 4. 构建状态检查
- [ ] dune build - 确认项目构建成功
- [ ] 记录构建时间和警告信息
- [ ] 检查是否有新的编译错误

# 5. GitHub状态检查  
- [ ] gh issue list --state open - 检查开放Issue
- [ ] gh pr list --state open - 检查开放PR
- [ ] 识别高优先级和维护者关注的问题

# 6. CI/CD状态检查
- [ ] 检查最近的CI运行状态
- [ ] 确认没有失败的自动化测试
- [ ] 验证部署管道正常运行
```

#### 🎯 任务优先级评估
```yaml
优先级评估标准:
  🚨 Critical (立即处理):
    - 维护者明确要求的紧急任务
    - 生产环境影响的严重Bug
    - CI/CD系统故障
    
  🔥 High (今日必完成):
    - 维护者评论的PR和Issue
    - 有明确deadline的技术任务  
    - 阻塞其他代理工作的问题
    
  📋 Medium (本周内完成):
    - 常规技术债务清理
    - 代码质量改进任务
    - 文档更新需求
    
  📝 Low (时间允许时处理):
    - 优化性改进
    - 实验性功能探索
    - 非关键的重构工作
```

### 🔧 技术实施质量标准

#### 代码质量检查清单
```markdown
每次代码变更前必须确认:
- [ ] **模块化原则**: 新增代码符合现有模块结构
- [ ] **命名规范**: 变量、函数、模块命名清晰一致
- [ ] **依赖管理**: 不引入不必要的模块依赖
- [ ] **错误处理**: 适当的错误处理和边界条件检查
- [ ] **性能考虑**: 不引入明显的性能问题
- [ ] **向后兼容**: 保持现有API的向后兼容性
```

#### 技术债务评估清单
```markdown
每次重构或新功能前评估:
- [ ] **复杂度影响**: 评估圈复杂度变化
- [ ] **重复代码**: 识别和消除重复逻辑
- [ ] **架构一致性**: 符合现有架构模式
- [ ] **文档完整性**: 关键功能有充分注释
- [ ] **测试覆盖**: 新功能有对应测试
- [ ] **维护成本**: 考虑长期维护难度
```

### 📋 PR提交质量流程

#### PR创建前检查
```bash
# 1. 本地质量验证
- [ ] dune build - 确保本地构建成功
- [ ] make test - 运行完整测试套件 (如果存在)
- [ ] git diff --stat - 确认变更范围合理
- [ ] 检查提交消息符合规范

# 2. 分支管理
- [ ] 确认在正确的feature分支上工作
- [ ] git rebase origin/main - 确保基于最新main分支
- [ ] 解决任何rebase冲突
- [ ] 确认分支命名符合规范: feature/agent-description
```

#### PR描述质量标准
```markdown
每个PR必须包含:
- [ ] **明确的Fix #issue-number引用**
- [ ] **详细的技术方案说明**  
- [ ] **变更影响范围评估**
- [ ] **测试验证情况说明**
- [ ] **代理审查清单填写**
- [ ] **技术债务影响评估**
```

### 🤝 代理协作质量保障

#### 与其他代理协作检查
```markdown
开始任务前确认:
- [ ] **无任务冲突**: 确认不与其他代理的工作重叠
- [ ] **依赖关系**: 识别对其他代理工作的依赖
- [ ] **影响评估**: 评估变更对其他代理工作的影响
- [ ] **沟通计划**: 必要时通过Issue/PR进行沟通

任务完成后确认:
- [ ] **工作成果记录**: 详细记录完成的工作
- [ ] **后续任务识别**: 识别和创建后续需要的任务
- [ ] **知识传递**: 通过文档分享重要发现
- [ ] **质量反馈**: 为其他代理的工作提供建设性反馈
```

## 应急响应流程

### 🚨 紧急情况处理清单

#### 生产环境问题
```bash
立即行动:
1. [ ] 评估问题严重程度和影响范围
2. [ ] 通知维护者@UltimatePea
3. [ ] 创建紧急修复分支: hotfix/critical-issue-description
4. [ ] 实施最小化修复方案
5. [ ] 快速测试验证修复效果
6. [ ] 创建紧急PR，标注"🚨 HOTFIX"
7. [ ] 等待Beta代理和Delta代理紧急审查
8. [ ] 协调快速合并和部署
```

#### CI/CD系统故障
```bash
诊断和修复:
1. [ ] 检查CI配置文件(.github/workflows/)
2. [ ] 验证依赖和环境配置
3. [ ] 检查测试失败原因
4. [ ] 实施修复并验证
5. [ ] 确保修复不影响其他功能
6. [ ] 记录故障原因和解决方案
```

#### 代理协作冲突
```bash
冲突解决流程:
1. [ ] 识别冲突的技术根源
2. [ ] 收集所有相关代理的意见
3. [ ] 分析不同方案的利弊
4. [ ] 寻求技术数据支持决策
5. [ ] 必要时请求维护者仲裁
6. [ ] 记录冲突解决过程和决策理由
```
