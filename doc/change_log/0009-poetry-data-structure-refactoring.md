## 改进概述

重构了 `src/poetry/poetry_rhyme_data.ml` 中的长函数 `rhyme_data_strings`，将100行的单一数据列表分解为结构化的模块化数据定义，显著提高了代码的可维护性和可读性。

## 问题描述

### 原有代码问题
- `rhyme_data_strings` 函数长达100行，全部为重复的元组定义
- 所有韵组数据混合在一个巨大的列表中
- 难以定位和修改特定韵组的数据
- 新增韵组需要在长列表中找到合适位置
- 代码重复度高，每个条目都是相同的模式

### 技术债务指标
- **函数长度**: 100行（超出40行标准150%）
- **重复模式**: 113个相同结构的元组定义
- **可维护性**: 低（修改特定韵组需要在长列表中查找）
- **可扩展性**: 差（添加新韵组困难）

## 解决方案

### 重构策略
1. **函数式组合**: 创建 `make_rhyme_group_data` 辅助函数消除重复
2. **数据模块化**: 按韵组类型组织独立的数据定义
3. **清晰分组**: 每个韵组有独立的数据声明
4. **组合式构建**: 使用 `List.concat` 组合所有数据

### 重构后的代码结构

```ocaml
(* 辅助函数 - 消除重复模式 *)
let make_rhyme_group_data group category chars =
  List.map (fun char -> (char, category, group)) chars

(* 模块化的韵组数据 *)
let an_rhyme_data = 
  make_rhyme_group_data AnRhyme PingSheng
    ["山"; "间"; "闲"; "关"; "还"; "班"; "颜"; "安"; "删"; "蛮"; "环"; "弯"]

let tian_rhyme_data = 
  make_rhyme_group_data TianRhyme PingSheng
    ["天"; "年"; "先"; "田"; "边"; "前"; "连"; "千"; "线"]

(* ... 其他韵组 ... *)

(* 组合所有数据 *)
let rhyme_data_strings =
  List.concat [
    an_rhyme_data;
    tian_rhyme_data;
    (* ... *)
  ]
```
