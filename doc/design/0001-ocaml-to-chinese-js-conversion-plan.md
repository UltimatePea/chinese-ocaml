# OCaml到中文JavaScript转换实施计划

**Author: Charlie, 规划代理专员**

## 项目概述

根据项目维护者@UltimatePea的要求（Issue #1708），需要将整个"骆言"编程语言编译器项目从OCaml转换为中文JavaScript，编译到JS/WASM执行。

## 当前项目状况分析

### 项目规模
- **主要源码文件**: ~500+ OCaml文件(.ml/.mli)
- **测试文件**: ~200+ 测试文件
- **核心模块**: 词法分析器、语法分析器、语义分析器、代码生成器、解释器
- **特殊功能**: 诗词编程支持、中文语法处理、古典风格语法
- **总代码行数**: 约30,000+行OCaml代码

### 核心模块识别
1. **词法分析器** (`src/lexer/`)
2. **语法分析器** (`src/parser*`)  
3. **AST定义** (`src/ast.ml`)
4. **类型系统** (`src/types*`)
5. **语义分析** (`src/semantic*`)
6. **解释器** (`src/interpreter*`)
7. **代码生成器** (`src/c_codegen*`, `src/codegen*`)
8. **诗词处理** (`src/poetry/`)
9. **内置函数** (`src/builtin*`)
10. **错误处理** (`src/error*`)

#### 1.3 函数名中文化
**关键要求**: 所有函数定义名称必须使用中文

转换规则示例:
```ocaml
(* OCaml原代码 *)
let parse_expression tokens = ...
let compile_file filename = ...
let check_types ast = ...
```

转换为:
```javascript
// 中文JavaScript
function 解析表达式(词元列表) { ... }
function 编译文件(文件名) { ... }  
function 检查类型(抽象语法树) { ... }
```

## 技术挑战与解决方案

### 挑战1：OCaml模式匹配
**解决方案**: 实现基于visitor模式的匹配系统
```javascript
function 匹配表达式(表达式, 分支列表) {
    for (let 分支 of 分支列表) {
        let 结果 = 尝试匹配(表达式, 分支.模式);
        if (结果.成功) {
            return 分支.处理函数(结果.绑定);
        }
    }
    throw new Error("匹配失败");
}
```

### 挑战2：OCaml类型推导
**解决方案**: 实现运行时类型检查器
```javascript
class 类型推导器 {
    推导类型(表达式) {
        // 实现Hindley-Milner算法
    }
}
```

### 挑战3：函数式编程特性
**解决方案**: 利用JavaScript函数式特性，使用immutable.js库

## 迁移原则

### 1. 保持功能完整性
- 所有现有功能必须在JavaScript版本中保留
- 特别是中文语法处理和诗词编程特性

### 2. 性能目标
- 编译速度不应比OCaml版本慢50%以上
- 内存使用保持合理水平

### 3. 中文化要求
- **所有函数名必须使用中文**
- 保持注释和文档的中文特色
- 维护代码的可读性

### 4. 兼容性要求
- 生成的代码能在Node.js和浏览器中运行
- 支持WASM编译目标
- 向后兼容现有.ly源码文件

## 风险评估

### 高风险项
1. **类型系统复杂度**: OCaml的类型系统很难在JavaScript中完美复现
2. **性能降级**: JavaScript性能可能显著低于编译后的OCaml
3. **开发工期**: 预计12周可能不够，需要预留缓冲时间

### 缓解策略
1. 分阶段实施，确保每阶段可验证
2. 建立完整的测试覆盖
3. 性能关键路径优先优化
4. 保持与维护者的频繁沟通
