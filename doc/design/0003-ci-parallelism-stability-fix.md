**PR**: #1814  

## 问题描述

### 现象
在PR #1814的开发过程中，发现了严重的CI不稳定性问题：

1. **并行测试执行失败**：`dune runtest` 默认并行执行导致：
   - 段错误 (SEGV)：多个测试进程导致信号冲突
   - 链接错误：`/usr/bin/ld` 报告符号表错误
   - 资源竞争：临时文件和内存访问冲突

2. **具体错误信息**：
   ```
   Command got signal SEGV.
   /usr/bin/ld: /tmp/build_a9ff50_dune/camlstartup0fcb24.o: .symtab local symbol at index 1329 (>= sh_info of 18)
   /usr/bin/ld: /tmp/build_a9ff50_dune/camlstartup0fcb24.o: error adding symbols: bad value
   collect2: error: ld returned 1 exit status
   ```

3. **根本原因**：并行测试执行在以下情况下不稳定：
   - 多个测试进程同时访问共享资源（韵律数据库、缓存文件）
   - 临时文件名冲突导致链接器错误
   - 线程安全问题（Mutex库的引入可能加剧了问题）

## 解决方案

### 核心策略：单线程测试执行

**原理**：通过 `-j 1` 参数强制 `dune runtest` 使用单线程执行，避免并行竞争。

### 具体实现

#### 1. CI配置更新
文件：`.github/workflows/ci.yml`
```yaml
- name: Run tests
  run: |
    opam exec -- dune runtest -j 1  # 添加 -j 1 参数
```

#### 2. 质量检查脚本更新  
文件：`scripts/quality/compile_check.sh`
```bash
if timeout 60 dune runtest -j 1 > "$test_output_file" 2>&1; then  # 添加 -j 1 参数
```

## 技术分析

### 为什么单线程执行解决问题？

1. **资源访问串行化**：避免多个进程同时访问：
   - 韵律数据库文件 (json_core.ml 的缓存机制)
   - 临时构建文件 
   - 共享内存区域

2. **链接器冲突消除**：
   - 避免多个链接器进程同时生成 camlstartupXXX.o 文件
   - 消除符号表竞争条件

3. **Mutex库兼容性**：
   - 单线程环境下，threads库的Mutex不会产生竞争
   - 避免进程间锁竞争

### 性能影响分析

- **测试执行时间增加**：从并行执行改为串行，预期增加30-50%时间
- **CI总时间影响**：测试阶段从~2分钟增加到~3分钟
- **可接受的权衡**：稳定性优于速度，确保CI可靠性
