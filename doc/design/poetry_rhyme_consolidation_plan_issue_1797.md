# Poetry韵律数据整合重构计划 - Issue #1797

**作者：** Alpha, 主要工作代理  
**日期：** 2025年7月30日  
**议题：** Fix #1797 - 优化Poetry模块：减少文件数量和消除代码重复

## 当前状况分析

### 问题严重性
- **韵律相关文件总数：** 124个文件
- **主要重复模式：** 相同的韵组数据在多个文件中重复定义
- **目录分散：** 数据分布在多个不同的目录结构中

### 具体文件分布
```
src/poetry/rhyme_data/          - 18个文件（各个韵组的独立文件）
src/poetry/data/rhyme_groups/   - 32个文件（按声调分类的韵组）
src/poetry/rhyme_groups/        - 14个文件（另一套韵组文件）
src/poetry/core/                - 9个韵律核心文件
src/poetry/                     - 51个其他韵律相关文件
```

### 主要重复内容
1. **韵组数据定义重复：** 安韵、天韵、思韵等基础韵组在多个位置定义
2. **API接口重复：** 查找、匹配、验证功能的多种实现
3. **类型定义重复：** 相似的数据结构在不同模块中重新定义
4. **JSON处理重复：** 多个JSON序列化/反序列化的实现

## 整合策略

### 第一阶段：核心数据统一（立即执行）

**目标：** 建立统一的韵律数据源
**时间：** 1周

**具体步骤：**
1. 创建新的统一韵律数据模块 `src/poetry/unified_rhyme_core.ml`
2. 合并所有韵组的基础数据（安、天、思、鱼、风、华、汇、江、月、曲、王韵等）
3. 提供统一的数据访问API
4. 删除重复的独立韵组数据文件

**影响文件：**
- 删除 `src/poetry/rhyme_data/` 目录下的18个韵组文件
- 合并 `src/poetry/data/rhyme_groups/` 中的重复定义
- 统一 `src/poetry/rhyme_groups/` 中的数据源

### 第二阶段：API层整合（后续）

**目标：** 统一韵律处理的API接口
**时间：** 1周

**具体步骤：**
1. 合并多个 `rhyme_*_engine.ml` 文件
2. 统一 `rhyme_json_*` 相关的JSON处理
3. 整合 `rhyme_query_*` 查询接口
4. 优化 `rhyme_cache` 缓存机制

### 第三阶段：清理和优化（最后）

**目标：** 删除废弃文件，优化性能
**时间：** 几天

**具体步骤：**
1. 删除不再使用的文件
2. 更新所有引用点
3. 优化数据加载性能
4. 完善测试覆盖
