## 问题概述

### 症状描述
当前骆言编译器在处理基础中文字符时出现严重回归，导致核心中文编程功能完全失效：

```
错误信息: LexError("不支持的字符: 吾 (非关键字的多字节字符)")
失败字符: 吾、定、加、之、乃等基础中文字符
影响语法: "吾有一数"、"设变量为"等基础语法无法使用
测试失败: 6/14 测试套件失败，包括核心功能测试
```

### 根本原因分析

通过代码审查发现问题源于 `src/lexer_chars.ml:98` 的字符处理逻辑：

```ocaml
(* 对于多字节字符，提供更好的错误信息 *)
raise (LexError ("不支持的字符: " ^ utf8_char ^ " (非关键字的多字节字符)", pos))
```

**问题机制**:
1. **关键字表设计问题**: 关键字表包含复合词如"吾有"，但词法分析器逐字符处理
2. **字符分类逻辑缺陷**: 单个中文字符被错误分类为"非关键字的多字节字符"
3. **Unicode优化副作用**: 最近的Unicode优化引入了过于严格的字符验证

## 技术分析

### 关键字系统架构

当前关键字系统包含多个层次：

```
1. basic_keywords_data.ml - 基础关键字
   - wenyan_keywords: [("吾有", `HaveKeyword); ("一", `OneKeyword); ...]
   
2. keyword_matcher_tables_ancient.ml - 古雅体关键字  
   - ancient_keywords: [("之", AncientParticleOf); ...]
   
3. keyword_matcher_core.ml - 核心匹配逻辑
   - 整合所有关键字表进行匹配
```

### 字符处理流程问题

```ocaml
(* 当前有问题的流程 *)
1. lexer_chars.ml:try_match_keyword() 尝试匹配完整关键字
2. 匹配失败时调用 handle_non_keyword_char()  
3. handle_non_keyword_char() 对中文字符抛出"不支持"错误
4. 即使字符是关键字组成部分也被拒绝
```

### 具体失败案例

**测试用例**: `"吾有一数名曰「数值」其值「四」也在「数值」"`

**失败流程**:
1. 词法分析器读取字符 '吾'
2. try_match_keyword() 查找"吾"作为完整关键字 -> 失败
3. handle_non_keyword_char() 判断为非ASCII字符
4. 抛出"不支持的字符: 吾"错误
5. 编译终止，用户代码无法工作

**应该的正确流程**:
1. 词法分析器读取字符 '吾'  
2. 发现可能是"吾有"的开始，继续读取
3. 读取到"吾有"完整关键字
4. 返回 HaveKeyword token
5. 继续处理后续字符

## 解决方案设计

### 短期修复方案 (紧急)

**目标**: 立即恢复基础中文编程功能

**技术方案**:
1. **修改字符处理逻辑**: 在 `lexer_chars.ml` 中增加中文字符白名单
2. **改进关键字匹配**: 支持前缀匹配和回溯机制
3. **错误处理优化**: 区分真正不支持的字符和关键字组成字符

**具体实施**:
```ocaml
(* 在 handle_non_keyword_char 中添加中文字符检查 *)
let is_chinese_keyword_char char = 
  (* 检查是否为已知关键字的组成字符 *)
  List.exists (fun (keyword, _) -> String.contains keyword char) all_keywords

let handle_non_keyword_char state pos =
  let utf8_char = get_current_utf8_char state in
  if String.length utf8_char = 1 then
    (* ASCII字符处理逻辑 *)
    handle_ascii_char state pos utf8_char
  else if is_chinese_keyword_char (utf8_char.[0]) then
    (* 可能是关键字组成部分，尝试更长匹配 *)
    try_longer_keyword_match state pos
  else
    (* 真正不支持的字符 *)
    raise (LexError ("不支持的字符: " ^ utf8_char, pos))
```
