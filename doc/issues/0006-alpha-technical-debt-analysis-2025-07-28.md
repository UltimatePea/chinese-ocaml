## 🔧 技术债务清理建议

### Phase 1: 核心模块拆分（风险可控）
**目标文件**: `src/poetry/rhyme_core_unified.ml` (854行)

**拆分方案**:
```
rhyme_core_unified.ml (854行) →
├── rhyme_core_types.ml (~100行) - 核心类型定义
├── rhyme_data_builder.ml (~200行) - 数据构建函数
├── rhyme_group_manager.ml (~200行) - 韵组管理逻辑
├── rhyme_query_engine.ml (~200行) - 查询和索引功能
└── rhyme_legacy_compat.ml (~150行) - 向后兼容接口
```

**关键优势**:
- 每个模块职责单一，便于维护
- 保持现有API完全兼容
- 减少单文件复杂度
- 提升编译并行度

### Phase 2: 数据管理优化（性能提升）
**目标**: 优化大数据文件的加载和访问效率

**优化方案**:
- 实现数据懒加载机制
- 优化JSON解析性能
- 实现数据缓存策略

### Phase 3: 代码重复消除（维护性改善）
**目标**: 消除重复的韵律数据处理逻辑

**方案**: 
- 统一韵组数据访问接口
- 合并重复的类型转换函数
- 建立统一的错误处理机制

## 📋 实施方案
