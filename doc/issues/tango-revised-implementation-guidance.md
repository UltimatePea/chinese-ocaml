## 🔍 正确的诊断方法论

### Step 1: 验证问题是否真实存在
在任何"Unbound module"问题分析前，必须：

```bash
# 1. 验证当前构建状态
dune build

# 2. 检查具体模块是否存在
find . -name "*data_loaders*" -type f

# 3. 验证库是否正确安装
dune exec -- ocamlfind query yyocamlc.poetry_data_loaders

# 4. 测试具体的模块引用
grep -r "Poetry_data_loaders.Unified_loader" src/
```

### Step 2: 区分问题类型

| 症状 | 可能原因 | 解决方案类型 |
|------|----------|-------------|
| `Unbound module "X"` | 1. 模块不存在 | 创建新模块 |
| | 2. 库未正确暴露 | 修复dune配置 |
| | 3. 依赖关系错误 | 调整依赖 |
| | 4. 引用路径错误 | 修正import路径 |
| | 5. 构建顺序问题 | 调整构建依赖 |

### Step 3: 最小化验证
```ocaml
(* 创建简单测试文件验证模块可用性 *)
(* test_module_access.ml *)

  let config = Poetry_data_loaders.Unified_loader.default_config in
```

## 📋 标准化的库暴露问题诊断流程

### 诊断检查清单
```markdown
## "Unbound module"问题诊断标准流程

### 1. 基础验证 (5分钟)
- [ ] 运行 `dune build` 验证当前构建状态

### 2. 依赖分析 (10分钟)  
- [ ] 检查dune文件的libraries列表

- [ ] 确认引用路径的正确性

### 3. 历史分析 (5分钟)

- [ ] 查看是否有其他修复已解决问题

### 4. 最小化测试 (10分钟)
- [ ] 创建简单测试文件验证模块访问
- [ ] 隔离测试具体的引用路径
- [ ] 确认问题的最小重现场景

总时间: 30分钟最大，远小于实施解决方案的时间
```

### 解决方案优先级

1. **无操作** (问题不存在) - 0分钟
2. **配置调整** (dune依赖) - 5分钟
3. **路径修正** (import路径) - 15分钟
4. **别名模块** (简单转发) - 30分钟
5. **新模块实现** (最后选择) - 数小时

### 工具层面
```bash
#!/bin/bash
# check_module_dependencies.sh
# 验证关键模块的可用性

echo "验证Poetry模块依赖..."
dune build --only-optional-for-foreign-stubs 2>&1 | grep -i "unbound\|not found" || echo "✅ 所有模块依赖正常"

echo "验证关键库安装..."
for lib in poetry_core poetry_data poetry_data_loaders; do
    if ocamlfind query yyocamlc.$lib > /dev/null 2>&1; then
        echo "✅ $lib 库正常"
    else
        echo "❌ $lib 库缺失"
    fi
done
```
